## v0.2.0 自动备份（已完成，准备发布）

项目已决定跳过 v0.1.1，直接进入 v0.2.0。当前权威产品方案见 `SaveLink-v0.2.0自动备份方案.md`。

已确认：

- SaveLink 启动后立即检查一次，之后默认每 10 分钟检查一次。
- 自动备份使用全局开关并默认开启，作为设置页第一个正式设置项，不为每个游戏单独配置。
- 当前存档与最近成功快照不同才创建，不变则跳过。
- 游戏运行期间允许读取；正式快照必须通过稳定性和完整性校验。
- 本地快照创建成功后立即上传百度网盘。
- 每个游戏保留最近 30 个未锁定历史记录；锁定记录不计入 30 个且不设数量上限。
- 清理旧记录的最终目标同时覆盖本地仓库和百度网盘；只完成本地清理不算 v0.2.0 保留策略完成。
- 多设备出现冲突时暂停自动覆盖，由用户选择本机、云端或两边都保留。

当前实现已统一计数手动、自动和云端接收的未锁定快照。云端删除失败时保留本地文件和记录并写入 `delete_failed`，后续周期重试；只有云端 `.ok`、`.zip` 均删除成功后才删除本地快照。绿色版实机、真实百度上传/下载/恢复、31→30 联合删除和跨设备时间修复均已验收。

跨设备快照时间已统一：SQLite 中的快照时间固定保存为秒精度 UTC RFC 3339，旧版本机分钟格式和带偏移 RFC 3339 会在打开数据库时自动迁移；前端统一转换为用户本地时间显示。混合来源快照的最近记录、内容去重和 30 条淘汰均按真实时刻判断，已有云端协议 v1 对象无需重传。

### 发布后补充验收（不阻塞 v0.2.0）

- 真实断网时自动上传失败、保留本地和恢复联网后的重试。
- Token 失效及百度限流时的自动上传恢复。
- 真实百度云端删除中途失败后，`delete_failed` 的后续续做。

## 已完成能力

### 游戏管理

- 添加游戏，选择单个存档目录。
- 测试读取目录，显示文件数量和总大小。
- 游戏列表展示名称、快照数量、最近快照时间。
- 编辑游戏名称与存档路径。
- 编辑时可重新选择目录、测试读取、保存修改。
- 移除游戏：删除 SaveLink 内部游戏记录、该游戏快照记录和快照仓库文件。
- 移除游戏不会删除真实存档目录。

### 快照管理

- 手动创建快照。
- 存档未变化时返回 NoChange，不重复创建。
- 时间线展示创建时间、备注、文件数量、大小、创建原因。
- 快照详情抽屉可修改备注；备注目前承担“快照命名”的作用。
- 快照可锁定/取消锁定。
- 锁定快照不可删除。
- 未锁定快照可删除。
- 旧版 `before_restore` 记录作为普通历史备份兼容展示，当前版本不再创建。

### 恢复流程

- 恢复前先校验目标快照；目标损坏则不碰真实存档。
- 当前已等于目标时不覆盖；其余情况直接恢复，不自动创建或复用恢复前快照。
- 确认弹窗明确提醒第一版不会自动备份当前存档，用户可先手动创建快照。
- 覆盖恢复采用同盘临时目录 + rename 替换；`.old` 保留到最终校验通过后才删除，最终校验失败会换回原目录。
- 恢复后校验真实存档内容与目标快照一致。
- 恢复失败页已按错误类型精修：
  - 快照损坏、已回滚的恢复失败：明确提示本次恢复未修改真实存档。
  - 极端的未回滚失败：提示真实存档可能已被改动，要求核对存档目录。
- 存档目录缺失时，UI 已支持“创建目录并恢复”和“取消”。
- “重新选择目录并恢复”暂未做；它依赖更完整的编辑路径/恢复联动，暂不算核心缺口。

### 版本信息与设置入口

- 当前版本号直接显示在首页 SaveLink 标题旁，不需要进入设置页查看。
- 顶部齿轮打开设置页，当前第一个正式设置项是“自动备份”全局开关，默认开启并显示 10 分钟检查间隔。
- 设置状态保存在 SQLite `app_settings.auto_backup_enabled`；从关闭切换为开启时立即执行一次检查。
- `get_app_info` 以及打开/复制 AppData 路径的底层实现仍保留，当前设置页不展示这些内部路径。
- 绿色版和安装版继续共用 `%APPDATA%\com.daiq.savelink` 数据目录。
- 保留的 `@tauri-apps/plugin-opener` 权限只允许 `$APPDATA` 与 `$APPDATA/**`，不开放整个磁盘。

### 打包

- `savelink-app/build-portable.bat` 用于生成面向普通用户发布的绿色版目录、ZIP 和 SHA-256 文件。
- `savelink-app/build-installer.bat` 用于生成绿色 exe、NSIS 和 MSI。
- 两个脚本都会自动定位 MSVC 环境并在构建前关闭本工作区正在运行的 SaveLink。
- 脚本已具备针对锁文件/瞬时错误的重试能力。

### 百度账号连接

- 快照时间线已提供“上云”按钮；未连接时触发百度官方 OAuth 页面。
- 使用系统默认浏览器授权，并由 `127.0.0.1:53682/oauth/callback` 本机回调接收授权码。
- 回调校验随机 `state`，同一时间只允许一个授权流程，超时后自动结束等待。
- Token 保存在 `%APPDATA%\com.daiq.savelink\credentials\baidu-oauth.json`；SQLite `cloud_accounts` 只保存 `token_ref`，Token 不传入 React、不写日志。
- 2026-07-15 已用正式绿色版完成真实授权、回调和本机持久化验证。
- 未连接时授权成功后自动继续上传；已连接时直接打包并上传当前快照。
- 快照上传入口已由纯图标改为图标加文字：默认 `上传`、进行中 `上传中`、成功 `已上云`、失败 `重试`；成功状态持久化为 `uploaded`，重复上传由协议层保证幂等。
- access token 临近过期时自动使用 refresh token 刷新并落盘；账号解绑/切换作为低频增强后置，凭据加密是 v0.1.x 的优先安全加固项。
- 2026-07-16 已实测百度应用目录中生成同一快照 ID 的 `.zip` 与 `.ok`。
- 顶栏“云端存档”可按游戏展示云端快照；只读发现阶段不会创建本机游戏。
- 用户点击下载后先校验 zip 大小与 SHA-256，再校验解压后的内容指纹；全部通过后才写入本机 `repository` 和 SQLite。
- 接收成功后才创建未绑定的本机游戏，且绝不带入设备 A 的真实存档路径；绑定前禁止创建快照和恢复。
- 已通过 `%APPDATA%\com.daiq.savelink-device-b-test` 隔离数据目录实测，顶栏明确显示“设备 B 隔离测试”，不会触碰正式 SaveLink 数据目录。
- 未绑定游戏的主操作为“绑定存档目录”：选择路径后先只读扫描，扫描成功才允许确认；绑定只更新本机 SQLite 路径，不创建快照、不恢复、不上传。
- 目录为空时明确说明绑定后仍需用户另行选择快照恢复；目录已有文件时，绑定页和恢复确认页都提醒用户恢复不会自动备份，可先手动创建快照。
- 2026-07-16 设备 B 已绑定假目录 `D:\door\模拟存档\艾尔登法环-机器2` 并手动恢复，目标快照恢复出 1 个文件、54 B，恢复文件与本机快照仓库副本 SHA-256 完全一致。旧版曾生成恢复前备份，当前版本不再创建。
