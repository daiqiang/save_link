## 结论先行

百度网盘 API 已经跑通，可以作为 SaveLink 第一个云存储后端继续开发。

百度网盘不适合把一条快照的大量小文件逐个上传和下载。第一版云端快照物理格式应确定为：

```text
本地：repository/snapshots/{snapshot_id}/（由 FsStore 管理）
上传：临时打包成单快照 {snapshot_id}.zip
云端：{snapshot_id}.zip + {snapshot_id}.ok
下载：下载 zip -> 校验 -> 解压 -> 内容校验 -> 通过 FsStore 写入本机 repository
```

这里的“单快照 zip”不是整个 SaveLink 数据区的 `latest.zip`。新增一条快照只上传这条快照的 zip，不重传历史快照。

`FsStore` 是本机快照存储的代码实现，`repository` 是它管理的实际数据目录。云端 `{snapshot_id}.ok` 是云同步层生成的 JSON 发布标记，不是把本机 `repository/snapshots/{snapshot_id}.ok` 原样上传。

## 2MiB 基准测试方法

为避免文本数据被压缩到极小而导致结果失真，测试数据使用不易压缩的随机字节生成。

两个场景：

1. `single-2m`：1 个 2MiB 文件。
2. `multi-2m-100`：100 个文件，合计 2MiB。

每个场景都使用同一份源数据对比：

```text
目录镜像：逐文件上传/下载
单快照 zip：先本地打包，再上传/下载一个 zip
```

目录在计时前按需创建，避免上一轮递归上传中重复 `mkdir` 夸大目录镜像耗时。上传、列表、filemetas、下载均分开记录。

## 结果解读

### 1. 普通账号 API 传输偏慢，但可用

2MiB 单文件上传约 5s，折算约 0.4MiB/s。2MiB 单文件下载约 26–28s，折算约 75–80KiB/s。

这个速度不适合在游戏启动前强制同步大量数据，但可以支持用户主动上传/下载快照，并在 UI 中显示真实进度、大小和预估时间。

### 2. 小文件的主要问题是请求数

同样是 2MiB：

- 100 小文件目录上传 46.76s，单 zip 上传 4.88s，目录镜像约慢 9.6 倍。
- 100 小文件目录下载 61.12s，单 zip 下载 27.55s，目录镜像约慢 2.2 倍。

因此，快照里包含多个文件时，单快照 zip 明显更适合百度网盘。

### 3. 本地打包开销可接受

测试程序通过启动 PowerShell `Compress-Archive` 打包，包含额外的进程启动开销。即使把 4.38s 本地打包计入，100 文件场景的“打包 + 上传”约 9.26s，仍显著快于目录镜像的 46.76s。

正式产品应使用 Rust zip 库或等价本地打包实现，不依赖 PowerShell。

## 已确定的产品/技术决策

1. 本地快照继续由 `FsStore` 以目录形式保存在 `repository` 中，不因云同步强制改成 ZipStore。
2. 百度网盘的云端快照物理格式使用“一条快照一个 zip”。
3. zip 上传完成后，由云同步层生成并上传云端 `.ok`。云端存在 zip 但没有 `.ok` 时，视为未完成上传，其他设备必须忽略。
4. 下载后先验证 zip 大小和 sha256，再解压到本机临时目录。
5. 解压后必须再验证 SaveLink 已有的 `content_hash + file_count + total_size`，通过后才能由 `FsStore` 写入本机 `repository`。
6. 云上传输不能直接写入真实游戏存档目录；只有用户主动恢复时才走现有安全恢复链路。

## 尚未验证的产品化问题

本轮已证明基础 API 可用，但不等于所有产品化风险都已消失。尚需验证：

- `refresh_token` 长期轮换与过期后重新授权。
- 换一个未注册开发者的普通百度账号，是否只需授权同一个 SaveLink 应用就能使用。
- 正式上线审核、权限说明、隐私政策和测试账号材料。
- 长时间/高频调用的 API 限流和风控。
- 删除 API、失败上传清理和断点续传。
- 超过单步上传边界后的预上传/分片上传。
- 不同时段、不同网络、会员/非会员的速度波动。
- 多设备同时修改云端元数据时的冲突处理。

## 当时的下一步（现已完成）

不再继续扩大纯性能 POC。下一个工作单元应是 SaveLink 正式云同步最小闭环：

```text
上传一条本地快照
-> 模拟另一台电脑/另一套本地数据目录
-> 读取云端时间线
-> 下载该快照
-> 双重校验并通过 FsStore 写入本机 repository
-> 登记本机 SQLite 元数据
-> 在本机时间线可见
-> 使用现有安全恢复链路恢复
```

上述协议已经在 `SaveLink云端快照协议V1.md` 中定稿，Fake 双设备跨数据目录闭环也已通过。当时计划实现 `BaiduNetdiskStore` 并在真实百度网盘上复验同一服务流程；该工作随后已完成，正式客户端的普通账号双电脑上传、发现、下载、绑定和恢复也已验收通过。
