## 背景

第一轮市场机会调研已经确认：游戏存档时间机器项目值得做，云端方向应采用 API-first 的可插拔存储后端，而不是依赖某个网盘客户端的同步目录。

百度网盘是第一优先调研对象，原因是：

- 国内用户认知度高。
- 普通网盘空间较大，用户接受度高。
- 相比坚果云，没有免费用户 `1GB/月` 上传、`3GB/月` 下载这类小流量约束。
- 百度网盘同步空间不适合作为主路径，用户实测同步空间只有 `1GB`。
- 文件夹自动备份更像上传最新文件的通道，不能替代存档历史版本系统。

## 当前认识

百度网盘不能简单当作 NAS 使用。

NAS/SMB/WebDAV 更接近“远程文件系统”，应用可以相对直接地读写路径。百度网盘开放平台则是受控 API 服务，需要开发者按平台流程接入：

```text
注册登录百度账号
→ 完成实名认证
→ 创建应用
→ 接入 OAuth 授权
→ 调用网盘 API
→ 测试运行
→ 正式上线前提交应用审核
```

这意味着百度网盘更适合作为“对象存储后端”，不适合作为“透明远程硬盘”。

需要特别区分两个角色：

- 开发者：创建应用、拿 AppKey/SecretKey、配置授权、准备上线审核材料。
- 普通用户：只需要在 SaveLink 里点击“连接百度网盘”，登录/扫码并授权。

因此，当前官方 API 路线虽然需要创建应用，但不应该要求每个用户自己创建应用。正确的产品模式是 SaveLink 官方创建一个应用，所有普通用户授权这个应用访问自己的百度网盘。

老文章中“不用自己创建应用”的做法，多数是使用百度早期示例应用或公开 AppKey，例如 `pcstest_oauth`。这适合理解原理或临时测试，但不适合正式产品：

- 应用身份不属于我们，稳定性和权限不可控。
- 上传目录固定到示例应用目录，例如 `/apps/pcstest_oauth/`，产品名称和数据归属都不清晰。
- 旧 PCS 接口和 `response_type=token` 直接复制 access token 的方式不适合面向普通用户。
- 一旦示例应用、旧接口或公开 AppKey 被关闭，产品会整体失效。

对本项目来说，正确使用方式应该是：

```text
SaveLink 本地生成历史快照
→ 生成 manifest.json 和 hash
→ 调用百度网盘 API 增量上传快照对象和云端元数据
→ 另一台设备通过 API 拉取云端元数据
→ 下载新增快照对象
→ 校验 hash
→ 恢复到本地测试目录或真实存档目录
```

## 好消息与风险

好消息：

- 百度网盘开放平台文档显示，测试运行阶段可以直接使用 API，无需先提交正式上线审核。
- 用户已完成开发者注册并创建应用，应用层级的主要概念风险已经降低。
- 普通用户不需要创建百度开放平台应用；创建应用是 SaveLink 开发方的接入工作。
- OAuth、应用目录、上传、覆盖、列表、下载和 sha256 校验 POC 已于 2026-07-09 跑通。
- 2026-07-13 已完成 2MiB 单文件/100 小文件基准测试，证明单快照 zip 显著减少 API 请求开销。
- 2026-07-15 正式 Rust `BaiduNetdiskStore` 已实现并通过真实百度网盘对象上传、列表、下载、校验和删除冒烟。
- 2026-07-15 正式绿色版已跑通系统浏览器授权、`127.0.0.1` 回调、授权码换 Token、本机持久化和重启后连接状态识别。
- 2026-07-16 正式绿色版已跑通“点击快照上云 -> zip/.ok 上传 -> SQLite `uploaded` -> 绿色勾选”，并在百度客户端确认云端对象成对存在。
- 2026-07-16 设备 B 隔离数据目录已跑通“只读发现 -> 下载 zip -> 双重校验 -> 写入本机仓库/SQLite -> 未绑定目录保护”，真实双设备传输闭环成立。

风险：

- 正式上线需要应用审核，可能涉及应用名称、应用介绍、权限说明、隐私政策、测试账号、开发者承诺等材料。
- API 权限可能存在目录、配额、限流、风控、会员权益等限制。
- 当前开发者账号的桌面授权体验已验证；普通用户账号范围、应用正式上线审核后的页面和授权稳定性仍需验证。
- 如果只能写入 `/apps/应用名/`，需要确认这是否影响云端目录设计。
- 桌面客户端不适合明文内置 SecretKey；如果百度 OAuth 不支持适合桌面端的安全授权方式，可能需要一个轻量授权中转服务。

## POC 目标与结果

第二轮调研目标不是做完整产品，而是验证百度网盘能否作为第一个云存储后端。

该 POC 已完成。完整证据见 `百度网盘API-POC报告-20260714.md`。

最小 POC 链路：

```text
创建百度网盘开放平台测试应用
→ 完成 OAuth 授权
→ 上传 cloud-manifest.json / games.json / snapshots.json
→ 上传一个模拟快照目录
→ 上传一个单快照 zip
→ 列出云端快照
→ 下载指定快照目录或单快照 zip
→ 校验 hash
→ 下载到本地测试目录并校验内容
```

实际 POC 云端目录：

```text
/apps/savelink/
  cloud-manifest.json
  metadata/
    games.json
    snapshots.json
  snapshots/
    snap_dir_case/
      snap_001/
      snap_001.ok
    snap_zip_case/
      snap_002.zip
      snap_002.ok
```

该目录只用于验证 API 能力，不是产品正式协议。正式 v1 改为 `/apps/savelink/v1/games/{cloud_game_id}/` 下的 `game.json` 和单快照 zip + `.ok`，不使用全局 `games.json` / `snapshots.json`。

实际本地实验工程：

```text
D:\door\codex_workspace\save_link_poc\baidu-netdisk-poc\
  src\
  work\
  out\
```

该目录是 SaveLink 主仓库之外的实验工程，不是产品运行时、构建或发布内容。

## 验证状态

已验证：

- 开发者实名认证、创建应用和配置 OAuth 回调。
- 测试运行阶段可直接使用 API。
- 当前开发者百度账号可通过 SaveLink 应用的 OAuth 页面授权并完成本地回调。
- 应用可在 `/apps/savelink/` 下创建多级目录、上传、覆盖、列表和下载。
- JSON、中文路径、小文件、目录镜像和单快照 zip 都能完整往返并通过 sha256 校验。
- 2MiB 单文件上传约 5s，下载约 26–28s。
- 100 文件合计 2MiB 时，目录上传 46.76s，zip 上传 4.88s；目录下载 61.12s，zip 下载 27.55s。
- 正式适配器可将 `savelink/v1/...` 逻辑路径映射到 `/apps/savelink/v1/...`，并支持 CreateOnly/Overwrite、分页列表、stat、filemetas/dlink 下载和幂等删除。
- 正式适配器通过环境变量临时注入 POC Token 的真实冒烟，测试文件在校验后已删除，凭据未进入仓库。
- 正式客户端可从快照“上云”按钮打开百度官方授权页，通过本机回调换取 Token；Token 保存在 AppData 独立 JSON，SQLite 只保存位置引用，Token 不传前端、不写日志。
- 正式客户端可在隔离设备 B 数据目录中发现并下载既有云端快照；发现不创建本机游戏，接收成功后才创建不含设备 A 路径的未绑定游戏。
- 2026-07-23 已由两台真实电脑和非开发者普通百度账号完成授权、上传、发现、下载、绑定和恢复；普通用户无需创建自己的百度应用，也无需预先启动百度网盘客户端。
- 2026-08-05 已公开发布 SaveLink v0.1.0。

尚未验证：

- 正式上线审核的周期、材料和权限边界。
- 桌面客户端 Token 当前为用户 AppData 下的明文 JSON；v0.1.0 已按该状态发布，加密存储是 v0.1.x 的优先安全项，解绑/切换仍为低频增强。
- 失败上传后的远端孤儿清理、断点续传和超过 2 GiB 后的预上传/分片上传。
- 长时间/高频调用的 API 配额、限流和风控。
- 不同网络、时段、会员/非会员的速度波动。

## 初步设计判断

百度网盘 API 后端不应该承载版本逻辑，只承载存取逻辑。

产品层负责：

- 游戏识别或手动配置。
- 快照生成。
- 快照元数据。
- 云端元数据维护。
- hash 校验。
- 恢复前备份当前存档。
- 冲突检测和分支保留。

百度网盘后端只负责：

- 上传对象。
- 下载对象。
- 列出对象。
- 删除对象。
- 查询对象元数据。

抽象接口可以先设计为：

```text
putObject(path, localFile)
getObject(path, localFile)
listObjects(prefix)
deleteObject(path)
statObject(path)
```

## 当前结论

百度网盘值得作为第一云后端候选，但不应被理解为 NAS。

它更像一个容量大、用户熟悉、但受平台规则约束的云对象存储后端。OAuth、基础文件 API 和快照数据完整性 POC 已经通过，可以进入 SaveLink 正式云同步最小闭环开发。

云同步传输格式以 `SaveLink云端快照协议V1.md` 为准：不把整个 `latest.zip` 覆盖上传作为主线；本地快照仍由 `FsStore` 以目录形式保存在 `repository` 中，上云时将每条快照单独打包为 `{snapshot_id}.zip`，上传成功后再生成并上传不可变云端 `{snapshot_id}.ok`。

Fake 双设备已完成“本机上传一条快照 -> 另一套本地数据目录发现并下载 -> 双重校验 -> 通过 `FsStore` 写入本机 `repository` -> 登记 SQLite”的无网络闭环。正式 `BaiduNetdiskStore` 也已完成，并通过真实百度对象上传、列表、下载和删除冒烟。

OAuth、本机凭据持久化、自动刷新、单快照真实上云、设备 B 真实发现/下载/接收、存档目录绑定及安全恢复已经完成，并已由普通百度账号在两台真实电脑上验收。百度网盘 API 对 SaveLink 第一版手动云同步已证明可行，v0.1.0 已公开发布；后续重点是断网与授权失效回归、Token 加密、平台审核和更大文件的分片上传，不再是基础 API 可行性问题。
