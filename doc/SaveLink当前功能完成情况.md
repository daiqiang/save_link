## 一句话结论

SaveLink 已公开发布 Windows 桌面版 v0.1.0，当前 v0.2.0 功能已完成并进入发布准备。除原有手动快照和跨设备恢复外，v0.2.0 已增加默认 10 分钟自动检查、变化后自动快照上云、每游戏 30 条未锁定记录联合清理，以及跨设备时间格式兼容。

MVP 已完成正式回归验收，`TC-17` 移除游戏不删除真实存档和 `TC-41` 启动自检清理残留均已补测通过。恢复链路已增加小文件/中文路径回归测试，并把恢复后校验加强为 `content_hash + file_count + total_size`。

云同步已完成真实百度双设备完整闭环：设备 A 上传 zip + `.ok`，设备 B 只读发现、下载、双重校验、接收至独立仓库，再绑定本机假存档目录并由用户手动恢复。恢复文件与本机目标快照 SHA-256 一致。接收不会带入设备 A 路径，绑定不会自动恢复。core 当前 80 个默认测试全绿，J/L 两个真实联网测试均已按需运行通过；Tauri 自动上传状态选择测试 2 个全绿。

2026-07-23，代强和朋友进一步使用两台真实电脑及非开发者普通百度账号完成全链路人工验收。结论：普通用户可以直接授权并使用 SaveLink，不需要注册百度开发者或创建自己的应用；SaveLink 通过百度开放 API 工作，不要求本机预先打开或持续运行百度网盘客户端。

2026-08-05，`v0.1.0` 已在 GitHub 发布绿色版 ZIP 与 SHA-256，Apache License 2.0 已落库；GitHub 为主仓库，Gitee 为国内镜像，代码和标签均已同步。当前发布 ZIP 生成时间早于标签中的最后一个应用代码提交，需重新打包并替换附件，确保二进制与 `v0.1.0` 标签完全一致。

## 当前架构状态

- 客户端形态：Windows 桌面 C/S 架构应用，Tauri 壳 + React 前端 + Rust 后端命令层。
- 核心逻辑：`savelink-core`，纯 Rust service/repo/store 抽象，独立于 Tauri。
- 数据持久化：SQLite，数据库位于用户 AppData 下。
- 快照仓库：当前由 `FsStore` 以目录形式管理，实际数据位于用户 AppData 下的 `repository/`。
- 前后端调用：React 组件通过 `src/lib/api.ts` 统一调用 Tauri `invoke`，组件内不直接散落 invoke。
- 云同步路线：不再以 `latest.zip` 或整库 `savelink.db` 原样同步作为主线；百度网盘 POC 已通过，云端快照协议 v1 已定稿为按游戏目录发现的单快照 zip + `.ok`；详见 `SaveLink云端快照协议V1.md`。
- 云存储适配：`SqliteRepo` 已实现 `CloudStateRepository`；`FakeCloudObjectStore` 保护无网络同步测试；`BaiduNetdiskStore` 将逻辑路径映射到 `/apps/savelink/v1/`，实现真实 HTTP 对象操作。
- 百度账号连接：Tauri 已提供连接状态和发起授权命令；Token 独立保存在 AppData `credentials/baidu-oauth.json`，SQLite `cloud_accounts` 只保存 `token_ref`。
- 自动备份：Tauri 后台线程启动立即检查，之后每 10 分钟检查；全局开关持久化在 `app_settings`，默认开启。
- 自动上云：仅自动创建的快照由后台立即上传；未授权不弹浏览器，授权失效、断网和限流时保留本地等待后续周期重试。
- 自动保留：所有来源的未锁定记录统一计入 30 条，锁定记录不计入；云端 `.ok`、`.zip` 删除成功后才删除本地快照。
- 时间口径：快照时间在 SQLite 中统一为秒精度 UTC RFC 3339；旧本机分钟格式和带偏移云端格式自动迁移，界面统一按用户本地时区显示。

## 已完成功能

### 1. 游戏管理

- 添加游戏。
- 选择一个存档目录。
- 测试读取目录，显示文件数量和总大小。
- 游戏列表展示游戏名、快照数量、最近快照时间。
- 游戏信息落库，关闭再打开仍保留。
- 编辑游戏名称。
- 编辑游戏存档路径。
- 编辑时可重新选择目录、测试读取、保存修改。
- 移除游戏。
- 移除游戏会删除 SaveLink 内部的该游戏记录、快照记录和快照仓库文件。
- 移除游戏不会删除真实存档目录。

### 2. 快照创建与管理

- 手动创建快照。
- 如果存档未变化，创建快照返回“无变化”，不重复写入新快照。
- 快照时间线展示创建时间、备注、文件数量、大小、创建原因。
- 快照备注可编辑；目前备注基本承担了“快照命名”的作用。
- 快照可锁定/取消锁定。
- 锁定快照不能删除。
- 未锁定快照可删除。
- 旧版 `before_restore` 记录继续作为普通历史备份展示，当前版本不再创建。

### 3. 恢复流程

- 可从时间线恢复指定快照。
- 恢复前先校验目标快照，目标损坏则不碰真实存档。
- 当前已等于目标时不执行覆盖；其余情况直接恢复，不自动创建或复用快照。
- 确认页提醒第一版不会自动备份当前存档，用户若需保留当前进度应先手动创建快照。
- 恢复采用同盘临时目录 + rename 替换，`.old` 在最终校验通过后才删除；校验失败会尝试恢复原目录。
- 恢复后会校验真实存档内容与目标快照一致。
- 恢复失败文案已按错误类型优化：
  - 快照损坏、备份失败、已回滚的恢复失败：明确提示本次恢复未修改真实存档。
  - 未回滚的极端恢复失败：保留谨慎提示，要求用户核对存档目录。
- 存档目录缺失时，已支持“创建目录并恢复”。
- 存档目录缺失时，用户也可以取消。
- “重新选择目录并恢复”暂未做，因为它和更完整的“编辑游戏路径/恢复联动”有关，目前不是核心缺口。

### 4. 版本信息与设置入口

- 当前版本号直接显示在首页 SaveLink 标题旁。
- 顶部齿轮打开设置页，当前展示第一个正式设置项“自动备份”，默认开启并显示 10 分钟检查间隔。
- `get_app_info`、路径复制和 `@tauri-apps/plugin-opener` 打开路径的底层实现仍保留，当前设置页不展示内部数据路径。
- 绿色版和安装版共用 `%APPDATA%\com.daiq.savelink` 数据目录。
- opener scope 继续只允许 `$APPDATA` 和 `$APPDATA/**`，不开放整个磁盘。

## 已知未完成或需要总规划判断的点

### 1. 快照仓库仍是目录复制，不是 zip

当前本地快照仓库能用，但不是压缩包。后续如果关心空间占用和快照文件数量，可以规划 ZipStore 或 ResticStore。这不阻塞云同步：上传时将 `repository/snapshots/{snapshot_id}/` 临时打包为单快照 zip；下载后完成双重校验，再通过 `FsStore` 写入本机 `repository`。

### 2. 多存档目录还没做

底层模型已有 `save_paths: Vec<PathBuf>` 这种方向，但当前 UI 和恢复主要按单目录使用。多目录会影响扫描、快照、恢复、原子性、错误提示，建议单独立项。

### 3. 恢复进度事件还没完整接到前端

后端 service 有进度回调概念，但当前 Tauri command 里还是空回调。现在流程可用，但还没有真正的细粒度进度条/步骤事件。

### 4. 启动自检已接入，剩余真实窗口场景验收

`startup_self_check` 已在 core 中实现并有测试覆盖，当前 Tauri setup 会在 `AppState::init` 后、`app.manage(state)` 前显式调用。前端命令可用前会先清理上次异常中断留下的 Writing 半成品，并续做云端已删后中断的 Deleting 本机快照。后续正式回归时，可补真实窗口场景验收。

### 5. 自定义应用图标已完成

SaveLink 云链 V9 已生成网页 favicon 和 `src-tauri/icons/` 全套应用图标，窗口、任务栏、托盘及安装包配置均已接入，窗口/任务栏显示已由代强实机确认。发布体验仍需继续清理正式包工程测试标识，并在重新打包的 v0.1.0 产物中复测托盘和安装包图标。

### 6. 保留的设置组件只开放 AppData 范围的打开权限

这是有意收窄权限。虽然当前齿轮入口不展示设置对话框，保留的设置组件也只能打开 SaveLink 自己的数据目录和仓库目录。不要为了方便直接开放整个磁盘。

### 7. 全仓 Rust 格式尚未单独收口

当前 `rustfmt` 已可用，本轮新增 Rust 文件已单独格式化。全量 `cargo fmt --check` 会同时报告大量旧文件历史格式差异，因此本轮没有混入全仓机械格式化；后续可单独做一次格式提交。

### 8. 百度 Token 仍是明文文件

v0.1.0 将 OAuth Token 保存在 `%APPDATA%\com.daiq.savelink\credentials\baidu-oauth.json`。Token 不进入前端、不写日志、不上传云端，但文件本身尚未使用 DPAPI、Credential Manager 或 Tauri Stronghold 加密；这是 v0.1.x 的优先安全加固项。

### 9. v0.1.0 发布附件需要重新生成

当前本地绿色版 ZIP 生成于 2026-07-30 11:09，早于标签包含的 11:27“托盘增加划线”提交。应从 `v0.1.0` 标签对应提交重新执行 `build-portable.bat`，完成冒烟回归后替换 GitHub Release 附件。

## v0.2.0 完成状态

v0.2.0 的目标是让 SaveLink 定期检测存档变化，自动创建快照并立即上传百度网盘。当前权威方案见 `SaveLink-v0.2.0自动备份方案.md`。

已确认：

1. 启动后立即检查一次，之后默认每 10 分钟检查一次。
2. 自动备份使用全局开关并默认开启，作为设置页第一个正式设置项。
3. 内容变化才创建快照，游戏运行期间允许读取，但不得发布不稳定或未校验的文件。
4. 本地快照成功后立即上传百度网盘。
5. 每个游戏保留最近 30 个未锁定历史记录；锁定记录不计入 30 个、不设数量上限且不会被自动清理。
6. 删除旧记录的最终目标同时覆盖本地仓库和百度网盘，不能只实现本地清理。
7. 多设备冲突由用户选择，不允许后台自动覆盖。

本地专项、真实百度上传、跨 profile 下载恢复、31→30 联合删除、旧库时间迁移和设备 B 本地化显示均已验收。手动、自动和云端接收的完整未锁定快照已经统一计入 30 条。项目已确认这些结果足以发布 v0.2.0。

发布后继续补充但不阻塞本次发布的项目：真实断网重试、Token 失效或限流、真实百度删除中途失败、另一设备提前删除对象，以及多设备冲突选择交互。npm、Cargo、Tauri 和打包元数据已统一为 `0.2.0`，下一步从本次版本提交生成正式绿色版 ZIP 和 SHA-256。
