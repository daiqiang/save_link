# SaveLink 桌面应用 · 人工手动测试计划

> 本测试计划全部基于已审阅的源码与设计文档findings，逐条由测试人员手动执行。
> 操作步骤中引用的按钮、字段、文案均为应用内**确切文本**（来自源码）。
> 凡findings未覆盖到的信息，本文档会明确标注「findings 未提及」，不臆造。
>
> **安全提醒（来自设计文档 MVP 试用警示）**：当前快照存储为「目录复制，非压缩 zip」。请先用**不重要的测试目录**验证，第一次切勿指向你唯一的真实存档目录。

---

## 1. 测试准备

### 1.1 安装应用

1. 拿到安装包 `SaveLink_0.1.0_x64-setup.exe`（NSIS 安装包；findings 另提到也有 MSI 4.0M / 独立 exe 11M 两种产物）。
2. 双击 `SaveLink_0.1.0_x64-setup.exe`，按安装向导完成安装。
3. 安装完成后从开始菜单或桌面启动 SaveLink。

> 注意：findings 指出**应用图标仍是 Tauri 默认图标**（自定义图标为 TODO），这是已知现象，不算缺陷。

### 1.2 应用数据存储位置（真实路径）

应用所有数据写在 Windows 用户的 APPDATA 目录下，bundle 标识为 `com.daiq.savelink`：

- **数据根目录**：`%APPDATA%\com.daiq.savelink\`
- **SQLite 数据库文件**：`%APPDATA%\com.daiq.savelink\savelink.db`
- **快照仓库目录**：`%APPDATA%\com.daiq.savelink\repository\`
- **每个快照的文件树**：`%APPDATA%\com.daiq.savelink\repository\snapshots\{快照ID}\`
- **每个快照的完成标记文件**：`%APPDATA%\com.daiq.savelink\repository\snapshots\{快照ID}.ok`（内容是该快照的内容哈希）

> 在文件资源管理器地址栏直接粘贴 `%APPDATA%\com.daiq.savelink` 回车即可打开该目录，用于人工核对数据库与快照文件是否真实生成。
>
> 注意：界面「快照仓库」一栏显示的是**写死的文案** `使用默认位置：D:\SaveLink\Repository`，与上面真实路径**不一致**——这是 UI 占位文本，核对真实文件请以 `%APPDATA%\com.daiq.savelink\repository\` 为准。

### 1.3 创建假的测试存档数据（可复制粘贴）

不要用真实存档。请用下面命令做几个假存档目录。打开「命令提示符（cmd）」，逐条粘贴执行：

**测试目录 A（含 3 个假存档文件）：**
```
mkdir "%USERPROFILE%\savelink_test\saveA"
echo hello-save-1 > "%USERPROFILE%\savelink_test\saveA\slot1.sav"
echo hello-save-2 > "%USERPROFILE%\savelink_test\saveA\slot2.sav"
echo config-data  > "%USERPROFILE%\savelink_test\saveA\config.ini"
```

**测试目录 B（空目录，用于「空目录可快照」用例）：**
```
mkdir "%USERPROFILE%\savelink_test\saveB_empty"
```

**测试目录 C（含子目录与中文文件名，用于路径用例）：**
```
mkdir "%USERPROFILE%\savelink_test\saveC\子目录"
echo boss-before > "%USERPROFILE%\savelink_test\saveC\存档1.sav"
echo deep-file   > "%USERPROFILE%\savelink_test\saveC\子目录\存档2.sav"
```

记下这些目录的完整路径（如 `C:\Users\你的用户名\savelink_test\saveA`），下面用例中要用「选择目录」或手动粘贴。

> 修改/新增/删除存档文件用于「内容变化检测」用例时，可用类似命令，例如改一个文件：
> `echo changed-content > "%USERPROFILE%\savelink_test\saveA\slot1.sav"`
> 新增一个文件：`echo new > "%USERPROFILE%\savelink_test\saveA\slot3.sav"`
> 删除一个文件：`del "%USERPROFILE%\savelink_test\saveA\slot3.sav"`

### 2.6 还原快照（最高风险，重点测试）

> **安全原则（来自设计文档五条安全规则）**：每次还原前必须先自动备份当前真实存档（reason=before_restore）；若自动备份失败，还原必须中止且真实存档一字节不动；还原是「整目录替换」而非「合并」；目标快照损坏时不得触碰真实存档；真实存档目录缺失时不得静默创建。
>
> **重要 findings**：还原进行中的三步进度（备份/恢复/校验）是**固定节奏的演示动画（每步 700ms）**叠加在真实异步调用之上——进度条不代表真实后端步骤事件（后端进度回调当前为空操作）。
>
> **另一处实现细节（影响 TC-41 / TC-42 / TC-54）**：还原对话框的执行逻辑没有错误处理（无 try/catch）。若还原中途后端报错（目标快照损坏、存档目录缺失、目录被占用等），对话框很可能**停在「正在恢复」界面不动**——既不跳到「恢复完成」，也不弹错误提示。这属于已知的前端短板，遇到时请记录，并到 `%APPDATA%\com.daiq.savelink` 与真实存档目录核对数据是否被改动。

## 3. 已知未实现 / 暂不测试

以下功能 findings 明确为**未实现/占位/未接通**，不编写正向测试步骤，仅核对其「不可用」表现（已在上文相关用例覆盖占位提示的，列于此处汇总）：

- **设置**：点击仅弹 `设置：MVP 占位入口`，无设置界面。
- **帮助**：点击仅弹 `帮助文档：后续补充`，无帮助界面。
- **编辑游戏**：点击仅弹 `编辑游戏：demo 暂未实现`，无编辑界面。
- **多存档目录**：数据结构虽支持 `save_paths` 数组，但 UI 只展示/编辑/操作第 1 个路径（`save_paths[0]`），添加对话框也只能填 1 个目录。
- **「快照仓库」自定义位置**：界面显示写死文案 `使用默认位置：D:\SaveLink\Repository`，不可编辑，且与真实路径不一致。
- **存档目录缺失后的用户选择流程**（创建并还原 / 重新选择 / 取消）：核心 `restore_with_choice` 存在但**未接入任何 Tauri 命令**，UI 无法完成后续选择，只能显示错误（见 TC-42）。
- **启动自检清理「writing」残留**：核心 `startup_self_check` 存在但**未在启动时调用**，无法从 UI 验证。
- **还原真实进度事件**：后端进度回调为空操作，UI 三步进度为固定 700ms/步的演示动画，非真实步骤事件。
- **压缩 zip 存储**：当前为目录复制（`FsStore`），zip 为 TODO。
- **二期及以后**（findings/PROGRESS 明确不做）：文件监听、退出游戏自动快照、保留/清理策略、游戏识别（Ludusavi manifest）、云同步（百度网盘/WebDAV/NAS）、自定义应用图标。
- **清空备注**：后端 `update_snapshot_meta` 传 None 表示「不变」，无法把已有备注置为 null（见 TC-30 注记）。
