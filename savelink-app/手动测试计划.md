## 1. 测试准备

### 1.1 产物位置

绿色版：

```text
savelink-app/src-tauri/target/release/savelink-app.exe
savelink-app/src-tauri/target/release/bundle/portable/SaveLink_0.4.0_windows_x64_portable.zip
savelink-app/src-tauri/target/release/bundle/portable/SaveLink_0.4.0_windows_x64_portable.zip.sha256.txt
```

安装包：

```text
savelink-app/src-tauri/target/release/bundle/nsis/SaveLink_0.4.0_x64-setup.exe
savelink-app/src-tauri/target/release/bundle/msi/SaveLink_0.4.0_x64_en-US.msi
```

绿色版和安装版共用同一个数据目录：

```text
%APPDATA%\com.daiq.savelink\
├── credentials\baidu-oauth.json
├── cloud-work\
├── savelink.db
└── repository\
```

### 1.2 准备假存档目录

在命令提示符或 PowerShell 中创建测试数据：

```bat
mkdir "%USERPROFILE%\savelink_test\saveA"
echo hello-save-1 > "%USERPROFILE%\savelink_test\saveA\slot1.sav"
echo hello-save-2 > "%USERPROFILE%\savelink_test\saveA\slot2.sav"
echo config-data  > "%USERPROFILE%\savelink_test\saveA\config.ini"

mkdir "%USERPROFILE%\savelink_test\saveB_empty"

mkdir "%USERPROFILE%\savelink_test\saveC\子目录"
echo boss-before > "%USERPROFILE%\savelink_test\saveC\存档1.sav"
echo deep-file   > "%USERPROFILE%\savelink_test\saveC\子目录\存档2.sav"
```

也可以使用仓库内已有的假数据：

```text
acceptance-data/saveA
acceptance-data/saveB_empty
acceptance-data/saveC
acceptance-data/edit-path-target
```

## 2. 启动与基础布局

### TC-01 启动应用

步骤：

1. 启动绿色版 `savelink-app.exe`，或安装后启动 SaveLink。
2. 等待主窗口出现。

预期：

- 窗口标题为 SaveLink。
- 顶栏显示 `SaveLink` 和 `本地存档时间线`。
- 左侧为游戏列表，右侧为详情/空状态。

### TC-02 数据目录创建

步骤：

1. 启动 SaveLink。
2. 打开 `%APPDATA%\com.daiq.savelink`。

预期：

- 目录存在。
- `savelink.db` 存在。
- 创建快照后会出现 `repository\`。

### TC-03 设置入口

步骤：

1. 点击顶栏右侧齿轮按钮。

预期：

- 弹出提示 `设置功能：后续补充`。
- 不打开旧版设置对话框；当前产品暂不向用户展示该页面，这不算缺陷。

### TC-04 帮助入口

步骤：

1. 点击顶栏右侧帮助按钮。

预期：

- 目前仍弹出提示 `帮助文档：后续补充`。
- 帮助页尚未实现，这不算缺陷。

## 3. 首页版本号与发布外观

### TC-05 首页版本号

步骤：

1. 启动 SaveLink，查看顶栏左侧产品名称。

预期：

- `SaveLink` 标题旁直接显示当前版本，例如 `v0.4.0`。
- 无需点击设置按钮即可确认版本。

### TC-06 窗口图标

步骤：

1. 启动绿色版或安装版。
2. 查看窗口标题栏和 Windows 任务切换界面。

预期：

- 显示 SaveLink 云链 V9 自定义图标。
- 不显示 Tauri 默认图标，也不出现模糊、透明边缘异常或明显变形。

### TC-07 任务栏与托盘图标

步骤：

1. 查看 Windows 任务栏中的 SaveLink 图标。
2. 点击窗口关闭按钮，使应用隐藏到系统托盘。
3. 查看托盘图标，并通过托盘菜单重新打开应用。

预期：

- 任务栏和托盘均显示 SaveLink 云链 V9 图标。
- 点击关闭后应用仍可从托盘重新打开，图标不会退回默认图标。

### TC-08 绿色版恢复说明

步骤：

1. 使用 `build-portable.bat` 生成绿色版目录和 zip。
2. 打开绿色版目录中的 `README.txt`。
3. 使用 `.sha256.txt` 校验 ZIP，并确认打包提交与发布标签一致。

预期：

- 恢复说明明确写明当前版本不会自动备份恢复前存档。
- 说明建议用户先手动点击“创建快照”，不能再写“恢复前自动备份当前存档”。
- ZIP 内包含 `SaveLink/SaveLink.exe` 和 `SaveLink/README.txt`。
- SHA-256 校验通过，README 同时列出 GitHub 主仓库、Gitee 国内镜像和 Release 下载地址。
- 发布包必须从目标 Release 标签指向的提交重新生成，不得复用更早构建的 ZIP。

## 4. 添加游戏

### TC-09 打开添加游戏弹窗

步骤：

1. 点击左侧游戏列表标题行的 `+`。
2. 如果是空状态，也可点击空状态里的 `添加游戏`。

预期：

- 弹出标题为 `添加游戏` 的对话框。
- 有 `游戏名称`、`存档目录`、`快照仓库`。
- 有 `选择目录`、`测试读取`、`保存并创建`。

### TC-10 选择目录并测试读取

步骤：

1. 游戏名称填 `测试游戏A`。
2. 点击 `选择目录`，选择 `saveA`。
3. 点击 `测试读取`。

预期：

- 存档目录输入框显示真实路径。
- 测试读取成功后显示检测到的文件数量和大小。

### TC-11 正常添加游戏

步骤：

1. 在添加游戏弹窗中填好名称和 `saveA`。
2. 点击 `保存并创建`。

预期：

- 弹出 `游戏已添加，去创建第一个快照吧`。
- 弹窗关闭。
- 左侧出现 `测试游戏A` 并被选中。
- 右侧详情显示游戏名、路径、统计和 `创建快照` / `编辑游戏` 按钮。

### TC-12 添加游戏时名称为空

步骤：

1. 打开添加游戏弹窗。
2. 不填游戏名称。
3. 点击 `保存并创建`。

预期：

- 不创建游戏。
- 弹出 `请填写游戏名称`。

### TC-13 添加游戏时目录为空

步骤：

1. 填游戏名称。
2. 清空存档目录。
3. 点击 `保存并创建`。

预期：

- 不创建游戏。
- 弹出 `请至少选择一个存档目录`。

## 5. 编辑与移除游戏

### TC-14 打开编辑游戏弹窗

步骤：

1. 选中一个游戏。
2. 点击 `编辑游戏`。

预期：

- 打开标题为 `编辑游戏` 的弹窗。
- 不再是旧版“demo 暂未实现”提示。
- 显示游戏名称、存档目录、`选择目录`、`测试读取`、`移除游戏`、`保存修改`。

### TC-15 编辑游戏名称

步骤：

1. 打开编辑游戏。
2. 修改游戏名称，例如 `测试游戏A-改名`。
3. 点击 `保存修改`。

预期：

- 弹出 `游戏信息已保存`。
- 弹窗关闭。
- 左侧和详情页显示新名称。
- 重启应用后新名称仍保留。

### TC-16 编辑游戏路径

步骤：

1. 准备 `acceptance-data/edit-path-target` 或其他假目录。
2. 打开编辑游戏。
3. 点击 `选择目录`，选择新目录。
4. 点击 `测试读取`。
5. 点击 `保存修改`。

预期：

- 测试读取成功。
- 保存后详情页路径更新为新目录。
- 后续创建快照使用新目录。

### TC-17 移除游戏但不删除真实存档

步骤：

1. 新建一个专门用于删除测试的游戏，指向一个假目录。
2. 至少创建一个快照。
3. 点击 `编辑游戏`。
4. 点击 `移除游戏`。
5. 在确认弹窗中点击 `确认移除`。
6. 检查真实存档目录。

预期：

- 游戏从左侧列表移除。
- SaveLink 内部该游戏的快照记录和仓库文件被删除。
- 真实存档目录仍存在，文件未被删除。

## 6. 创建快照

### TC-18 创建第一个快照

步骤：

1. 选中指向 `saveA` 的游戏。
2. 点击 `创建快照`。

预期：

- 弹出 `快照已创建`。
- 时间线新增一条快照。
- 快照显示文件数量、大小、`手动创建`。
- 仓库中出现 `repository\snapshots\{snapshot_id}\` 和 `{snapshot_id}.ok`。

### TC-19 存档未变化不重复创建

步骤：

1. 不修改真实目录。
2. 再次点击 `创建快照`。

预期：

- 弹出 `存档未变化，未创建新快照`。
- 时间线数量不变。

### TC-20 修改文件后创建新快照

步骤：

1. 修改一个文件，例如：
   ```bat
   echo changed-content > "%USERPROFILE%\savelink_test\saveA\slot1.sav"
   ```
2. 点击 `创建快照`。

预期：

- 创建成功。
- 时间线新增一条快照。

### TC-21 空目录可创建快照

步骤：

1. 添加游戏，路径指向 `saveB_empty`。
2. 点击 `创建快照`。

预期：

- 创建成功。
- 快照显示 `0 个文件` 和 `0 KB`。

### TC-22 存档目录不存在时创建失败

步骤：

1. 添加一个路径不存在的游戏，或编辑游戏路径为不存在目录。
2. 点击 `创建快照`。

预期：

- 创建失败。
- 不新增快照。
- 真实磁盘上不创建该不存在路径。

### TC-23 打开快照详情

步骤：

预期：

### TC-24 修改备注

步骤：

1. 打开快照详情。
2. 在备注中输入 `Boss 前备份`。
3. 点击 `保存备注`。

预期：

- 弹出 `备注已保存`。
- 时间线该快照标题更新为新备注。

### TC-25 锁定与取消锁定

步骤：

1. 打开快照详情或点击时间线行内锁按钮。

预期：

## 8. 恢复快照

### TC-28 打开恢复确认

步骤：

1. 点击时间线快照行右侧 `恢复`。
2. 或打开快照详情后点击 `恢复这个版本`。

预期：

- 弹出 `恢复到这个存档版本？`。
- 显示游戏、目标版本、安全说明和当前存档目录。
- 明确说明当前存档会被覆盖，第一版不会自动备份，建议用户先手动创建快照。
- 底部有 `取消` 和 `恢复这个版本`。

### TC-29 恢复成功

步骤：

1. 创建至少两个不同内容的快照。
2. 再修改真实目录，使当前状态尚未创建过快照。
3. 选择较早快照恢复。
4. 点击 `恢复这个版本`。

预期：

- 进入 `正在恢复`。
- 完成后进入 `恢复完成`。
- 显示已恢复到目标版本。
- 时间线条数不变，不新增任何恢复前快照。
- 真实目录内容等于目标快照内容。

### TC-30 恢复是替换，不是合并

步骤：

1. 让当前真实目录多一个只属于当前状态的文件，例如 `extra.sav`。
2. 恢复到一个不包含 `extra.sav` 的旧快照。
3. 查看真实目录。

预期：

- `extra.sav` 不存在。
- 真实目录与目标快照一致。

### TC-31 可在两个已有快照之间往返恢复

步骤：

1. 为状态 A 和状态 B 分别手动创建快照。
2. 当前处于 B 时恢复 A。
3. 再恢复已有的 B 快照。

预期：

- 真实目录回到状态 B。
- 两次恢复均不新增快照，时间线条数不变。

### TC-31A 当前已经等于目标版本时不重复恢复

步骤：

1. 当前真实目录保持为某个已有快照的内容。
2. 对该快照点击 `恢复`，确认恢复。

预期：

- 完成页提示 `当前已经是这个版本`。
- 不覆盖目录，时间线条数不变。

### TC-31B 恢复不会自动保存当前未备份状态

步骤：

1. 修改真实存档，形成尚未手动创建快照的状态 C。
2. 记录时间线条数，然后恢复已有快照 A。

预期：

- 恢复成功，时间线条数不变。
- 状态 C 不会出现在时间线；这验证第一版不提供恢复成功后的自动反悔点。

### TC-32 目标快照损坏时不碰真实存档

步骤：

1. 选一个快照。
2. 手动修改其仓库目录内文件，或删除/修改对应 `.ok` 文件。
3. 记录恢复前真实目录内容。
4. 尝试恢复该快照。

预期：

- 恢复失败。
- 失败页提示类似 `快照已损坏`。
- 显示 `本次恢复未修改你的真实存档。`
- 真实目录内容与恢复前一致。

### TC-33 存档目录缺失时进入选择页

步骤：

1. 对某游戏创建至少一个快照。
2. 将该游戏真实存档目录改名或删除，使路径不存在。
3. 对快照执行恢复。

预期：

- 不静默写入。
- 进入 `存档目录不存在` 选择页。
- 显示原路径。
- 有 `创建目录并恢复` 和 `取消`。
- 页面提示到目前为止没有写入任何文件。

### TC-34 缺失目录时创建目录并恢复

步骤：

1. 在 TC-33 的选择页点击 `创建目录并恢复`。

1. 为同一个 ROM 保留正常的 `<ROM 文件名>.dsv`，并在 `Battery` 中放置 `.dsv-01`、`.dsv-02` 等即时存档。
2. 选择候选并确认添加。
3. 关闭当前添加弹窗后再次进入 DeSmuME 发现，检查匹配信息。

预期：

- 当前 `.dsv` 被识别为游戏内存档；`.dsv-01` 至 `.dsv-09` 不会被当作另一个可添加存档。
- SHA-256 相同的 ROM 可精确匹配，即使 ROM 文件名改变也不产生错误绑定。
- SHA-256 不同但 Header Title 和 Game Code 同时相同的 ROM 只能作为候选，并明确要求用户确认。

### TC-67 共享 Battery 的精确快照与恢复

1. 添加一个有 `.dsv` 的 DeSmuME 游戏，先创建快照 A。
2. 修改另一个游戏的 `.dsv` 或即时存档文件，确认当前游戏没有变化快照。
3. 修改当前游戏的 `.dsv`，创建快照 B。
4. 恢复快照 A，检查当前 `.dsv` 和其他游戏文件。

预期：

- 快照只包含当前游戏的 `.dsv`，不会把整个 `Battery` 目录打包。
- 其他游戏的 `.dsv`、`.dsv-01` 至 `.dsv-09` 在创建快照和恢复过程中保持不变。
- 恢复只替换当前游戏的目标 `.dsv`，不会清空 `Battery`，也不会删除目标之外的文件。

### TC-68 跨设备 ROM 改名后的恢复

1. 在设备 A 创建并上传 DeSmuME 快照。
2. 在设备 B 使用不同文件名但相同 SHA-256 的 ROM，或对 Header Title/Game Code 相同的候选执行人工确认。
3. 下载云端快照，完成本机 DeSmuME 绑定后恢复。

预期：

- 云端只包含 ROM 身份，不包含设备 A 的模拟器、ROM 或 Battery 绝对路径。
- 设备 B 恢复写入目标 ROM 文件名对应的 `.dsv`。
- 未完成本机 ROM 绑定时，创建快照和恢复按钮保持禁用；下载不自动改写真实存档。

### TC-69 DeSmuME 编辑与重新绑定

1. 打开已添加的 DeSmuME 游戏编辑页。
2. 检查当前 `.dsv` 路径为只读展示，修改游戏名称并保存。
3. 点击“重新绑定 DeSmuME”，重新选择模拟器目录和 ROM。

预期：

- DeSmuME 游戏不显示普通游戏的整目录编辑器。
- 修改名称不改变本机 ROM、Battery 或快照内容。
- 重新绑定成功后恢复按钮重新可用；绑定本身不创建快照、不恢复、不上传。

## 16. 当前已知限制与缺陷

- 帮助页仍是占位。
- “重新选择目录并恢复”未做完整闭环；当前只有“创建目录并恢复”和“取消”。
- 恢复真实进度事件未接入；恢复页显示整体进行中提示。
- 启动自检 `startup_self_check` 已接入 Tauri 启动路径；真实窗口残留清理场景待正式回归时补验收。
- 快照仓库是目录复制，不是 zip 压缩包。
- Steam 自动发现已接入；Elden Ring 配置父目录误入保护路径的问题已在 `18e1bb8` 修复，并通过自动测试、真实 Tauri 开发版和绿色版候选复验。
- 游戏程序识别的自动测试已覆盖 AppID、AppID 名称冲突回退、精确名称兜底、未知程序、名称前缀拒绝和真实 `.lnk` 往返；快捷方式和 EXE 已完成人工只读验收，目录入口仅保留历史验收记录。
- 当前“游戏程序”页面只允许快捷方式或 EXE；后端目录扫描仍由自动测试保护，但不再作为用户入口。
- 游戏自带备份镜像可能与主存档并列高可信；`HowManyDudes` 当前需要用户核对并只选择主存档，后续可优化排序或提示。
- 已配置游戏的常规自动备份仍使用 10 分钟轮询；动态发现只在待配置游戏由 SaveLink 启动时使用文件监听和退出事件，并在确认目录后创建首份自动快照。
- 已配置游戏可通过“启动游戏”直接启动；该按钮不进入动态发现状态机，也不会因为启动/退出自动产生候选。
- 百度真实上传、设备 B 接收、独立目录绑定和绑定后的安全恢复均已通过实机验收。
- 设置入口已提供自动备份开关；帮助入口仍为占位提示。
- 家中验收环境已安装 `rustfmt 1.9.0-stable`；本轮两个 Rust 改动文件通过 `rustfmt --check`。全仓检查会报告既有文件的历史格式差异，本轮未执行全仓格式化。
