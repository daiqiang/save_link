# SaveLink 低保真原型图

| --- | --- | --- | --- |

## 原型目标

本原型只验证 SaveLink 第一阶段的最小闭环：

```text
添加游戏
→ 选择存档目录
→ 创建快照
→ 查看时间线
→ 查看快照详情
→ 一键恢复
```

本原型暂不包含：

- 云同步。
- 百度网盘 API。
- 账号登录。
- 自动识别游戏。
- 游戏启动器。
- 自动快照策略。
- 高级设置。

## 页面 1：空首页 / 游戏列表页

### 用途

用户第一次打开 SaveLink 时，快速理解这是一个“管理游戏存档快照”的工具，并进入添加游戏流程。

### 线框图

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ SaveLink                                                        [设置] [?]   │
├───────────────────────┬──────────────────────────────────────────────────────┤
│ 游戏列表              │                                                      │
│                       │                                                      │
│ [ + 添加游戏 ]        │                                                      │
│                       │             还没有添加游戏                           │
│                       │                                                      │
│                       │             添加一个游戏后，                         │
│                       │             就可以为它创建存档快照和时间线。          │
│                       │                                                      │
│                       │             [ 添加游戏 ]                             │
│                       │                                                      │
└───────────────────────┴──────────────────────────────────────────────────────┘
```

### 关键交互

- 点击左侧或空状态里的“添加游戏”，打开“添加游戏弹窗”。
- 设置按钮先占位，MVP 可以不实现或只显示基础设置。
- 问号按钮先占位，后续可放帮助文档。

### 设计备注

- 空状态不要写太长说明。
- 第一屏只让用户做一件事：添加游戏。
- 不出现“仓库”“备份源”“Kopia”“Ludusavi”等概念。

## 页面 2：添加游戏弹窗

### 用途

让用户手动添加一个游戏，并指定真实存档目录。

### 线框图

```text
┌──────────────────────────────────────────────────────────────┐
│ 添加游戏                                                [x]  │
├──────────────────────────────────────────────────────────────┤
│ 游戏名称                                                     │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 艾尔登法环                                               │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ 存档目录                                                     │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ C:\Users\...\AppData\Roaming\EldenRing\7656...\          │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [ 选择目录 ]  [ 测试读取 ]                                  │
│                                                              │
│ 已检测到：3 个文件，12.4 MB                                  │
│                                                              │
│ 快照仓库                                                     │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 使用默认位置：D:\SaveLink\Repository                     │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [ 更改位置 ]                                                 │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                      [ 取消 ] [ 保存并创建 ]  │
└──────────────────────────────────────────────────────────────┘
```

### 关键交互

- “游戏名称”为必填。
- “存档目录”为必填。
- “测试读取”扫描目录，显示文件数量和大小。
- “保存并创建”保存游戏配置，并进入游戏详情页。
- 如果目录为空，允许保存，但提示“当前目录为空，创建快照时可能没有文件”。
- 如果目录无法访问，禁止保存。

### 设计备注

- 第一版只支持手动选择目录。
- 多存档目录可以后置；如果第一版要支持，也可以在“存档目录”下方增加“添加另一个目录”。
- “快照仓库”默认位置应自动生成，用户不需要理解仓库结构。

│   最近：21:30         │ [ 创建快照 ]  [ 编辑游戏 ]                           │

### 关键交互

- 点击“创建快照”，扫描存档目录并创建新快照。
- 如果文件没有变化，提示“存档未变化，未创建新快照”。
- 点击某条快照卡片，打开“快照详情抽屉”。
- 点击“恢复”，打开“恢复确认弹窗”。
- 点击“更多”，显示修改备注、锁定、删除等操作。

### 设计备注

- 时间线默认倒序，新快照在上。
- “恢复”按钮要明显，但不能误触，最终仍要经过确认弹窗。

## 页面 5：恢复确认弹窗

### 用途

恢复是高风险动作，必须确认，并明确告诉用户当前存档会被覆盖且第一版不会自动备份。

### 线框图

```text
┌──────────────────────────────────────────────────────────────┐
│ 恢复到这个存档版本？                                    [x]  │
├──────────────────────────────────────────────────────────────┤
│ 游戏：艾尔登法环                                             │
│ 目标版本：2026-06-18 21:30 Boss 前                            │
│                                                              │
│ 当前存档将被覆盖：                                            │
│                                                              │
│ SaveLink 第一版不会自动备份当前存档。                        │
│ 请确认当前进度已经创建快照，再恢复目标版本。                  │
│                                                              │
│ 当前存档目录：                                                │
│ C:\Users\...\AppData\Roaming\EldenRing\7656...\               │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                         [ 取消 ] [ 恢复这个版本 ]             │
└──────────────────────────────────────────────────────────────┘
```

### 恢复中状态

```text
┌──────────────────────────────────────────────────────────────┐
│ 正在恢复                                                     │
├──────────────────────────────────────────────────────────────┤
│ → 准备目标文件 → 替换存档 → 校验结果                         │
│                                                              │
│ 请不要在恢复过程中启动游戏。                                  │
└──────────────────────────────────────────────────────────────┘
```

### 恢复完成状态

```text
┌──────────────────────────────────────────────────────────────┐
│ 恢复完成                                                     │
├──────────────────────────────────────────────────────────────┤
│ 已恢复到：2026-06-18 21:30 Boss 前                            │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                      [ 回到时间线 ]           │
└──────────────────────────────────────────────────────────────┘
```

### 关键交互

- 恢复按钮文案使用“恢复这个版本”。
- 完成页只说明恢复到的目标版本；当前已等于目标时说明没有覆盖文件。
- 恢复不会新增快照；用户如需保留当前状态，应在确认前手动创建快照。

## 页面之间的关系

```text
空首页
  └─ 添加游戏弹窗
       └─ 游戏详情页 / 存档时间线
            ├─ 创建快照
            ├─ 快照详情抽屉
            │    └─ 恢复确认弹窗
            └─ 恢复确认弹窗
                 ├─ 恢复中状态
                 └─ 恢复完成状态
```

## MVP 核心判断点

这份低保真原型要验证的问题：

- 用户是否能理解“游戏详情页 = 这个游戏的存档时间线”。
- 用户是否知道从哪里创建快照。
- 用户是否知道从哪里恢复旧版本。
- “第一版不会自动备份”的风险提示是否足够清楚。
- “快照”“时间线”“恢复”这些词是否比“仓库”“备份源”“目标路径”更容易理解。

第一版低保真原型只需要这 5 个页面即可。
